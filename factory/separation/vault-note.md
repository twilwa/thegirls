# Red and Blue's proposed boundary

On this VPS there is no `/dev/kvm`, so Firecracker cannot run here as-is. Two separate locked Linux users, each with a rootless Podman container and a private persistent home, are the best practical fit. Both may edit their own memory/plugin code and restart their own service, but cannot edit the root-owned service policy or read the other's files. Network starts blocked; a separate, narrow gateway must pass live-routing tests first. Stage A's denials were mock tests, not evidence this real boundary works. We have not installed, logged in, or launched anything. Consult-Opus is approved through the captain's Max account, limited to two attempts per persona daily and logged, with Claude Code outside both homes. The existing login stays with firstmate; a tool-disabled adapter is needed to use it safely. We recommend a small new repository for provisioning, pending the captain's repository decision. There is no proposed new recurring spend.
