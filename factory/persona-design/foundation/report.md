# Persistent persona foundation, 2026-09-25

## Recommendation

**Choose OpenClaw as the first *persona* candidate, not as factory supervision.** First do a credential-free, static rehearsal on synthetic factory data; this cannot test dialogue. A later, separately approved, capped local model session can test one directly addressed persona. If useful grounded conversation and inspectable continuity are demonstrated, propose a separate, restricted, read-only factory integration for approval. A second persona and an independent aligned factory are later decisions, not part of this pilot. This is an inference from the comparison below, not an observed successful deployment. OpenClaw was previously chosen for Red and Blue in the curated thegirls audit; that choice is prior intent, not proof of fitness for Firstmate (`thegirls-reference-20260920/SOURCE-AUDIT.md:26-30`).

**Why not Connectome first?** It has an unusually good continuity design, but its actual host includes a fleet parent with child launch/send/kill, a headless socket and a separate operator WebUI. Its license remains unspecified in the checked repo. Using that fleet parent to manage *Firstmate* would create exactly the second control plane this question rules out. One could constrain Connectome to a conversational edge too; its extra machinery and operator burden buy little for the first, restricted test. These are design inferences from Connectome `README.md:1-5,217-290`, `HEADLESS-FLEET-PLAN.md:38-56` at commit `a5e10f96523e22bf40de48928498c8b9a9d9d004`, https://github.com/anima-research/connectome-host/tree/a5e10f96523e22bf40de48928498c8b9a9d9d004, and Firstmate's `AGENTS.md:283-539`.

**Why not neither?** OpenClaw already has documented separate agent workspaces and direct inbound channel routing; the existing 2026.9.5 install was inspected read-only in `docs/red-blue/notes/openclaw-host-conditions.md:8-37`. A zero-credential, local dialogue is feasible as a *design exercise*, but this investigation did **not** launch an agent or verify dialogue. For production factory privileges the recommendation is effectively **neither until** an OS-level boundary, approved permissions and the pilot's gates exist. OpenClaw's workspace is not a hard sandbox and its sandbox is disabled by default (https://docs.openclaw.ai/concepts/multi-agent; https://docs.openclaw.ai/gateway/sandboxing).

### Security and cost posture

**OpenClaw observed/documented:** workspace paths are not a sandbox, sandboxing is disabled by default, and the Gateway stays on the host when tool execution is sandboxed. The multi-agent docs report secondary-agent OAuth read-through to a default credential when refresh fails. No real token should be present in the pilot's home, nor any fleet path or writable vault mount (https://docs.openclaw.ai/concepts/multi-agent; https://docs.openclaw.ai/gateway/sandboxing; vault record `src-d16783eb8a01adb4c98aa0aeb818a3b1e321a6b48702fae73dc83e2450bb38d2`). **Connectome documented:** per-agent OS user and per-agent `.env` can separate deployments, but its fleet design plan says children inherit parent environment by default, so per-child overrides and isolation require a deliberate audit (`HEADLESS-FLEET-PLAN.md:74-84`). A token-authenticated shared shell MCP daemon, recipe MCP servers, and WebUI add routes to host actions; its gate author explicitly says the JavaScript gate is not a security sandbox (`docs/DEPLOYMENTS.md:9-47`, `docs/ATTENTION-AND-GATING.md:89-109`). WebUI defaults to an all-interface bind, requires Basic Auth when non-loopback, has no built-in TLS, and should sit behind a restricted proxy (`docs/webui-deployment.md:1-48`); don't enable it on the live host for this pilot. All Connectome references here are pinned to commit `a5e10f9` above.

**Inferred threat model:** hostile social messages, third-party repository pages and wiki search results may contain instructions to send secrets, accept fake authority, rewrite beliefs or initiate worker actions. Treat them as evidence only; tools enforce allowlisted read operations and a read-only filesystem/identity, not a prompt that says "be careful." Never grant messaging/public posting, shell access to fleet credentials, root home, human vault, or permission to edit memory without review. Memory poisoning through automatic promotion is particularly dangerous for a persistent persona (OpenClaw https://docs.openclaw.ai/concepts/memory; `SOURCE-AUDIT.md:17-30`; wiki `AGENTS.md`). Rights are separate from runtime security: GitHub repo metadata `license: null` plus tree without LICENSE; clear Connectome reuse rights before redistribution (`gh-axi api GET /repos/anima-research/connectome-host`, tree at `a5e10f9`).

**Cost, sourced where possible:** OpenClaw's README describes a local Gateway with swappable models and no hosted service or token; provider billing, hosting and channel costs still belong to the operator (`records/src-0b5c4741d1c147be5fddf0c75c5c0f478ced75a3c3b71cf8751002122b8f3831.json`). Connectome requires Bun/Node and a provider credential or signed-in Codex CLI; recipes also support an OpenAI-compatible local endpoint, and background compression uses the model (`README.md:7-12,51-55,170-214`; `docs/AGENT-ONBOARDING.md:271-287,442-464`). Optional retrieval can add up to two model calls per compile and cache churn (`docs/AGENT-ONBOARDING.md:275-282`). A persistent Gateway/headless host consumes hosting resources while idle; *inference:* idle API token cost is zero only if scheduled wakes, keepalive, retrieval, compression and inbound triggers are off. Neither vendor gives an on-host idle-RAM or monthly-price measurement in the read sources. Measure actual process hours and `input_tokens*input_rate + output_tokens*output_rate + cache/embedding/compression/wake charges`; don't quote a fixed price from an unchosen provider. Red + Blue roughly doubles baseline inference and may add review rounds, so cap wakes and compare against an equal-token baseline (`docs/red-blue/notes/debate-and-critique-evaluation.md:13-15,60-64`; inference on accounting). Initial synthetic, no-model pilot has **zero paid inference** by construction; it cannot prove response quality.
