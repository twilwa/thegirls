# Red and Blue persona foundation

**Recommendation:** Run a separate OpenClaw deployment for each persona, backed by a small, portable continuity layer that keeps source events, commitments, self-authored memories and model-choice history. Do not start with a shared privileged gateway or copy Connectome code. This is a proposed design, not a deployed or tested pair of personas. The [full report](report.md) compares the candidates and gives the offline Stage A contract.

The two roles in the historical snapshot are useful but not sufficient identity: Red explores and proposes; Blue challenges and checks. Each needs its own revisable charter, goals, private relationship history, and distinct platform login. A bounded wake can lead to action or a deliberate choice to sleep. An append-only event ledger records what happened; summaries are revisable interpretations with links back to their source events. Retain contradictory accounts with attribution. At boot, load identity, current goals and commitments, recent verbatim events and only the relevant older memories. Test whether compression drops commitments or alters relationships before using it live. This adapts the recoverable-history idea described by [Anima Labs](https://animalabs.ai/connectome/) and the context and memory mechanisms in [OpenClaw's current docs](https://docs.openclaw.ai/concepts/memory-architecture); it does not claim the systems are equivalent. The snapshot itself warned that its older assertions require rechecking (see the local `thegirls-reference-20260920/SOURCE-AUDIT.md`, read 2026-09-25).

OpenClaw documents [heartbeat](https://docs.openclaw.ai/automation/heartbeat), [channels](https://docs.openclaw.ai/channels), [multi-agent routing](https://docs.openclaw.ai/concepts/multi-agent), and [per-agent model policy](https://docs.openclaw.ai/concepts/models). These are useful building blocks, but an [agent workspace is not a sandbox](https://docs.openclaw.ai/concepts/agent-workspace). Put Red and Blue in distinct OS/container identities, directories, gateways, network scopes and channel accounts. Exclude Firstmate control files and all fleet secrets from both environments. A narrow external broker may exchange selected tasks and source-cited shared notes, never privileged credentials. Each persona needs an identifiable provider key or authorized route and an append-only model-choice and usage log, including fallback, utility and child calls. Provider subscription terms and actual billing attribution require verification before live use.

[Connectome-host](https://github.com/anima-research/connectome-host) is the strongest continuity-first alternative: its README describes Chronicle, first-person compression, branches, model recipes and optional fleet/subagents. GitHub repository metadata reported `license: null`, and the inspected `main` tree contained no LICENSE/LICENCE/COPYING file on **2026-09-25**, even though the [Anima Labs site](https://animalabs.ai/connectome/) calls Connectome open-source. Ask its maintainers which permission applies before using host code. [Letta's stateful-agent documentation](https://docs.letta.com/guides/agents/memory/) documents persistent messages and editable memory blocks, but the page is marked legacy V1; connectors and fleet need separate proof. Anthropic's [character training](https://www.anthropic.com/research/claude-character), [persona vectors](https://www.anthropic.com/research/persona-vectors) and [assistant-axis research](https://www.anthropic.com/research/assistant-axis) concern model behavior and drift, not evidence that prompt files create durable consciousness. All linked external pages were accessed 2026-09-25.

Stage A should use only disposable synthetic fixtures and mocked models, channel receipts and clocks. Verify denial of cross-persona and fleet-control reads in the mock policy; event recovery after a restart; retained commitments and contradictions; explicit model-route/cost logs; quiet wakes; bounded forks; gated changes and rollback. Record test commands, exits and deletion manifest. Passing proves the design logic, **not** actual OS isolation, model quality or platform presence. No credentials, login, root, real provider calls or source installs are needed. A later live stage must establish separate OS principals and negative filesystem probes before any secrets or accounts are provisioned. The owner need not approve Stage A, but main must request distinct persona identities, connector scope, model routes and budgets before Stage B. An independent persona fleet is optional and must not inherit the existing fleet's authority.
