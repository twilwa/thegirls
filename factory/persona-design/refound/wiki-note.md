# Red and Blue: foundation recheck, 2026-09-25

**What changed:** aligned model routing with the owner's Astra start, each persona's GPT-or-OpenRouter choice, Claude Code advisor boundary and OpenClaw's channel/task model support.

**Decision for design, not a deployment claim.** Use two isolated OpenClaw homes for messaging, wakes and model routing, with persona-owned context and memory code behind its exclusive plugin slots and an external, source-preserving event history. Keep the foundation choice conditional on a disposable composed-turn test. The unpublished task outputs `sr-persona-refound/report.md` and `sr-persona-refound/design-summary.md` carry the comparison; `sr-persona-design/report.md` defines the earlier Stage A contract. These paths are provenance, not vault links.

The owner wants continuity, control of their own code, platform presence and model choice ahead of assistant-style productivity. Persona is infrastructure and model together. The model, memory, context and recorded history all shape how Red or Blue continues; changing a model may change expression, and no file or model promises seamless identity transfer. Red should follow strange leads; Blue should challenge them. Neither is assigned a permanent model by this design.

OpenClaw v2026.8.1 was called "2.0"; this machine runs v2026.9.6 (eb377ac). Current SDK docs expose one active context engine and one active memory capability, but OpenClaw still owns gateway policy, turn preparation and much session behavior. A custom plugin can own memory and context; it does not let a persona deploy arbitrary code inside a privileged gateway. See [release notes](https://docs.openclaw.ai/releases/2026.8.1), [9.5](https://docs.openclaw.ai/releases/2026.9.5), [9.6](https://docs.openclaw.ai/releases/2026.9.6), [slot contract](https://docs.openclaw.ai/plugins/sdk-overview/memory-and-context) and [experimental harness contract](https://docs.openclaw.ai/plugins/sdk-agent-harness).

Both personas start on GPT-6 Astra through the OpenAI Codex subscription route. Pi lists `openai-codex/gpt-6-astra` (272K context, 128K maximum output); OpenClaw's canonical ref is `openai/gpt-6-astra`. Its 2026.9.6 docs confirm Codex subscription OAuth for Astra. Set the model-scoped `agentRuntime.id: "openclaw"` to keep turns on OpenClaw's embedded runtime with its context composition, using the selected OpenAI OAuth profile. Keep only the approved subscription OAuth profile in `auth.order.openai`; do not leave a Platform API-key profile or `OPENAI_API_KEY` fallback that could bill the API. This is a design route, not a configured login; no auth or model call was performed.

After starting on Astra, each persona decides whether to stay with subscription GPT models or switch to an OpenRouter model using the owner's promo credits until they run out. Each logs her model, route, budget/credit basis, reasons and observed effects. `quota-axi` at 2026-09-25 05:47 UTC reported 61% remaining in the shared Codex window with established confidence; it is not a per-persona allocation or per-call price. Pi also lists `openrouter/openai/gpt-6-astra` (1.1M context, 128K output), but OpenRouter authentication was unavailable and its credit balance remains unverified. No new Fable work or Sonnet use is proposed; whether personas are exempt from the owner's factory rules remains his open question, not a decision in this note.

OpenClaw supports model routing, not multi-model voting: `channels.modelByChannel` maps channel IDs or DM peer IDs to `provider/model` when the session has no active model override. Per-agent model settings and task-purpose slots include `agents.entries.*.model`, `agents.defaults.utilityModel`, `imageModel`, `pdfModel` and `mediaModels`; test the intended map in Stage A.

Blue's first self-directed project is research into public agent forums such as clawxiv, 4claw and similar spaces. She can compare accounts of changing models with accounts of editing memory, instructions or infrastructure. She chooses the posts and method, records claims and context, and decides what the findings mean for her own model and system. The survey has not been done here.

Claude is an external advisor only, not a day-to-day model. The proposed consult-Opus broker runs Claude Code on Opus 5.5 outside the persona boundary: it sends a limited, sanitized question under the owner's approved subscription, records the requesting persona, model, usage and budget, then returns text only. The answer is advice, not a decision or action; the session gets no persona files or operating authority, and no fleet credential enters a persona boundary. The broker is not provisioned; owner approval of its account, limits and operation is required before use. OpenClaw `attach` is not needed for day-to-day turns. Training or fine-tuning remains a later option only if a persona wants it, after data-handling and cost review. No training is proposed now.

Why not choose a rival now? [Connectome host](https://github.com/anima-research/connectome-host/blob/main/README.md) has Chronicle, first-person compression and wake events, but fewer turnkey chat routes in the evidence reviewed. [Issue 146](https://github.com/anima-research/connectome-host/issues/146) asks about its missing declared license; that did not determine the ranking. [Pi](https://github.com/badlogic/pi-mono) offers more direct code and context control but needs connector, wake and billing work. [goated](https://github.com/Endgame-Labs/goated) has Slack, Telegram and cron but leaves context to its coding runtime; its [Pi headless integration](https://github.com/Endgame-Labs/goated/blob/main/docs/PI_RUNTIME.md) exposes no compaction controls. Its [migration guide](https://github.com/Endgame-Labs/goated/blob/main/docs/OPENCLAW_MIGRATION.md) alleges token bloat, memory growth and identity drift from an unspecified setup. Those are maintainer claims, not verified measurements or the testimony of the agent the captain spoke with; that agent's reasons were unavailable.

Stage A remains offline and synthetic. Verify separate histories, source-linked summaries and commitments after compaction/restart, quiet wakes, requester-scoped memory search, attributable model routes, blocked cross-persona reads and rollback of unapproved changes. Test `channels.modelByChannel` plus the intended per-agent/task-purpose model slots, including that an active session override takes precedence. Add a test of what the model actually receives, atomic replay of an accepted turn and legacy fallback when the new context contract is absent. Compare Pi and Connectome against the same synthetic episodes if the OpenClaw adapter cannot own composition. Mock the Opus broker and its budget ledger without provider access. No trial was run for this note. A later live phase must separately check OS isolation, connector routing and provider bills.

Protect the boundary while experimenting: distinct non-root users or containers/VMs for Red and Blue, no Firstmate secrets or control files, no shared raw private history, and persona-attributable provider routes including fallback and child calls. A separately privileged reviewer promotes tested code proposals. An optional persona-owned fleet is welcome within its own authority; it is never a grant of the existing Firstmate fleet. Anthropic's [character work](https://www.anthropic.com/research/claude-character) and [persona-vector research](https://www.anthropic.com/research/persona-vectors) make model-dependent character drift worth testing. They do not establish consciousness or guaranteed identity transfer.
