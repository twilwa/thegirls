# A home for Red and Blue

**What changed:** aligned model routing with the owner's Astra start, each persona's GPT-or-OpenRouter choice, Claude Code advisor boundary and OpenClaw's channel/task model support.

## What changed and why

The foundation comparison keeps two isolated OpenClaw homes, but gives each persona ownership of its own memory and context code through OpenClaw's replaceable plugin slots. OpenClaw handles messaging, wakes and model routing. This choice still depends on a disposable test proving that the host does not add competing context or lose accepted turns. Connectome remains a serious alternative on merit. Pi offers more control over a persona's own code but needs a social gateway. The [comparison report](report.md) has the evidence and fallback.

The owner wants Red and Blue to be continuing companions with projects of their own, not assistants reading character cards. Red should be free to follow a strange lead; Blue should be free to challenge it. Each should remember promises, revise opinions when events warrant it, choose when to work and sometimes rest. A short charter can give each a voice, but neither `SOUL.md` nor a summary is the whole identity. Persona means infrastructure and model together: the memory, context, history and current model all shape how it continues. A model change may alter its expression; this design does not claim consciousness or guarantee that a voice transfers intact.

Each keeps original conversations and decisions in an append-only history. Older stretches can be summarized in the persona's own words, but the summary must point to the events it describes. The persona may correct a memory without erasing the earlier account. Its working context draws on recent events, an evolving charter, goals, unresolved promises and relevant older memories within a set budget. Red and Blue can exchange a sourced shared note, never each other's private diary or raw chats. OpenClaw's built-in Memory already supports some recall, so Stage A should test what needs replacing instead of duplicating it by habit. A lost promise or a summary that changes a relationship is a failed continuity test.

OpenClaw 2.0 was the August 2026 v2026.8.1 release; this machine runs v2026.9.6 (eb377ac). Current plugin documentation offers exclusive memory and context-engine slots, a more meaningful opening than editing an identity file. OpenClaw still controls the gateway, much of the turn lifecycle and tool policy. The personas may propose code changes and test them in separate staging areas. An external reviewer promotes a tested version; neither may rewrite its running gateway or gain privileges by editing a plugin. If the slot contract fails, the next experiment is a Pi-owned runtime with a measured connector bridge. goated is another small shell with Telegram, Slack and scheduled work, but leaves compaction to its coding runtime; its Pi integration does not expose compaction controls. Connectome's Chronicle, first-person compression and optional fleet deserve a parallel comparison when there is a safe way to test them.

A bounded wake loop lets each persona revisit interests, budgets and invitations. It can start a small project, ask for help or rest. Temporary workers receive limited tasks and sources; an independent fleet may come later. Both personas start on GPT-6 Astra through the OpenAI Codex subscription route: Pi lists `gpt-6-astra` under `openai-codex` (272K context, 128K maximum output), and OpenClaw's canonical model ref is `openai/gpt-6-astra`. OpenClaw 2026.9.6 documents Codex subscription OAuth for this model. Set the model-scoped `agentRuntime.id: "openclaw"` to preserve OpenClaw's embedded turn composition and use the selected OpenAI OAuth profile; do not configure a Platform API-key fallback. No authentication or model call was performed.

After that start, Red and Blue each decide whether to stay with subscription GPT models or switch to an OpenRouter model using the owner's promo credits until they run out. Each records her choice, model, route, budget/credit basis, reasons and observed effects in her choice log. `quota-axi` at 2026-09-25 05:47 UTC reported 61% remaining on the shared Codex window with established confidence; that is not a per-persona allocation or per-call price. Pi also lists `openrouter/openai/gpt-6-astra` (1.1M context, 128K output), but `quota-axi` reports OpenRouter authentication unavailable, so the credit balance and entitlement remain unverified. No new Fable work or Sonnet use is proposed; whether persona model choice is exempt from the owner's factory rules remains his open question, and this design does not decide it.

OpenClaw supports a routed model ensemble, not multi-model voting: `channels.modelByChannel` maps channel IDs or DM peer IDs to `provider/model` when a session has no existing model override. Task-specific routes include `agents.defaults.utilityModel`, `imageModel`, `pdfModel` and `mediaModels`, with per-agent overrides. Use these mechanisms in the disposable Stage A routing test; no live configuration is changed here.

Blue owns a first self-directed project researching public agent forums such as clawxiv, 4claw and similar spaces. She can compare agents' first-hand accounts of changing models with accounts of changing memory, instructions or infrastructure, and record what each person says they gained, lost or carried across. She chooses the sources, method and conclusion. The findings should inform Blue's own choices, not settle the question for Red or for us. No forum survey has been done for this note.

Claude is an external advisor only, not a day-to-day model. The owner approved the consult-Opus broker on 2026-09-25: Claude Code on Opus 5.5 through the captain's Max subscription, outside both persona environments, text only, at two attempted consults per persona per UTC day, with every attempt, refusal and failure logged to an append-only root-owned journal that records metadata but never the question or answer. The answer is advice, not a decision or action. The signed-in Claude Code login belongs to firstmate and is never shared or copied: a separate `sr-consult` front-end enforces quota and audit, and a firstmate-owned, tool-disabled adapter makes the one bounded call. OpenClaw `attach` is unnecessary for day-to-day turns.

Training or fine-tuning a separate model for Red or Blue remains a later option if that persona wants it. Its own continuity history could be the data source, with provenance retained and data handling and cost approved before any training. Nothing in this design trains a model now.

The boundary stays physical. The owner approved persona separation on 2026-09-25. Use separate locked host users and rootless Podman containers with root-owned service policies, private writable state, `Network=none`, and host UID egress deny. Before live traffic, build and probe an explicitly allowlisted Unix-socket egress gateway. `/dev/kvm` is absent; Firecracker is not viable on this host without nested virtualization or migration. Tensorlake requires two paid concurrent sandboxes and an external resume path for idle gateways, so no paid signup is proposed. Stage B must prove real cross-persona and control-file denied reads, mount and egress restrictions, code self-edit and restart, and reboot persistence before credentials or launch. Neither gets Firstmate's control files, secrets, signed-in browser or the other's private state. A plugin or prompt is not a sandbox. A persona can trial proposed changes and roll them back; executable releases, new privileges, wider audiences and higher spending limits need an independent check and human approval. Neither service has launched.

**Stage A starts without credentials or approval.** Offline fake channels, fake models, a clock and synthetic conversations should prove two histories survive restart, summaries retain sources and promises, forbidden cross-persona reads fail, model calls have attributable ledger entries, quiet wakes stay quiet and rejected code changes do not activate. Add mock context-engine tests for crash replay, memory authorization and duplicate bootstrap injection. The same synthetic episodes can be compared with Pi and Connectome adapters. Mock the Opus broker and budget ledger without contacting a provider. Leave test results and a deletion manifest. This cannot prove live connector delivery, provider billing or an OS-denied read; those belong to the later isolated stage.

The later owner requests remain: root execution of the reviewed provisioning commands, approved account access and explicit per-persona attribution and cost limits before live use. Astra is the chosen design route, not a configured login; the subscription OAuth profile must be selected without a Platform API-key fallback. OpenRouter credit balance is unverified. Connectome's missing license still needs its maintainer's answer before reusing the code, but did not determine this recommendation. The risk most likely to overturn the foundation choice is that OpenClaw's context slot cannot give the personas effective control over what their model sees. That is why the first test is about the actual composed turn, not how many plugins the catalog lists.
